## 1. 结论

现在是一个“窗口程序，里面顺带装了翻译”。目标形状是：

```
入口层（热键/托盘/按钮） → 策略层（认词/认句/选方案） → 能力层（翻译/词典） → 模型
                                ↑
                          Result（译文/词典/失败）
                                ↓
                        展示层（结果卡片）
```

界面从“应用本身”降级为“外壳”：它只做两件事——把操作系统的动作翻译成 `Intent`，把 `Result` 画出来。核心不再认识界面。

**第 1 步只切一刀**：把“要做什么”（Intent）和“做出来是什么”（Result）从 `app.py` 抽到独立模块。其余五处保持原样，用文档记录，不顺手改。

## 3. 目标架构

### 3.1 模块边界

| 模块 | 只负责 | 不负责 | 允许依赖 |
|---|---|---|---|
| `translator_domain.py` | Intent/Result 类型、词句判断、错误分类 | 网络、文件、界面 | 无（仅标准库） |
| `translator_core.py` | 结果归一化、`run_intent` 入口 | 配置存储、HTTP、界面 | domain、provider、settings |
| `translator_provider.py` | OpenAI 兼容请求、SSE 流式、取消 | 配置、业务策略、界面 | domain、requests |
| `translator_settings.py` | 路径、schema、原子写、DPAPI 加密、迁移 | 网络、界面 | 标准库 |
| `app.py` | 触发、剪贴板、配置窗、渲染、托盘、单实例 | 判断词句、拼提示词、解析错误 | domain、core、settings、Tk |

### 3.2 依赖规则

1. 依赖只能向下：`app → core → provider/domain`；`app` 与 `core` 都可读 `settings`；`settings` 与 `domain` 不 import 本项目其他模块。
2. 界面和 core 都不 import `requests`，不拼 URL，不解析响应。
3. core 不 import `tkinter`，不知道“弹窗”存在。
4. 失败只能在 domain 定义一次；provider 把网络/协议错误转成 `Failure`，core 收敛成 Result。

### 3.3 数据流

```
热键/按钮
   │ 原文
   ▼
build_intent(text) ──Intent(kind=word|text)──▶ run_intent(intent)
                                                    │
                                    ┌───────────────┼───────────────┐
                                    ▼               ▼               ▼
                              Translation       Definition       Failure
                                    └───────────────┴───────────────┘
                                                    │ Result
                                                    ▼
                                          _show_result 按类型渲染
```

## 4. 契约

### 4.1 Intent

| 字段 | 类型 | 说明 |
|---|---|---|
| `kind` | `"word"` / `"text"` | 只决定走词典还是翻译，不决定供应商 |
| `text` | `str` | 已去首尾空白；空串是合法输入，由 `run_intent` 返回 EMPTY |

判定规则与旧版一致：去掉首尾标点后，只含 ASCII 字母/连字符/撇号、无空格、长度 2–30 → `word`；其余 → `text`。

### 4.2 Result

| 类型 | 字段 | 用途 |
|---|---|---|
| `Translation` | `text` | 纯译文 |
| `Definition` | `word`、`uk`、`us`、`senses`、`raw` | 词典；`senses` 暂为 `list[dict]`（见 D4） |
| `Failure` | `kind`、`message`、`retryable`、`raw` | 失败；同时是异常类型，core 可直接抛、`run_intent` 可返回 |

### 4.3 失败分类

| kind | 触发 | 可重试 | 界面建议 |
|---|---|---|---|
| `config` | 没填密钥 | 否 | 提示去配置 |
| `auth` | 401 / 403 | 否 | 提示密钥无效 |
| `endpoint` | 404 | 否 | 提示地址或模型不对 |
| `rate_limit` | 429 | 是 | 提示稍后重试 |
| `server` | 5xx / 其他状态码 | 视情况 | 提示稍后重试 |
| `network` | 连接失败 / 超时 | 是 | 提示检查网络 |
| `parse` | 返回不是合法 JSON / 结构不对 | 否 | 有 `raw` 就显示原文 |
| `empty` | 空文本 | 否 | 提示先复制内容 |
| `unknown` | 未分类异常 | 否 | 显示错误信息 |

### 4.4 设计决策

- **D1 界面降级为适配器**：换界面（网页/悬浮窗/命令行）不动 core。
- **D2 Failure 同时是异常和结果**：减少一层包装；core 内部抛，边界统一转成返回值。
- **D3 词句判断归策略层**：将来加中文、代码、段落，只改 `build_intent`。
- **D4 `senses` 暂不拆成二层类型**：本步只切顶层契约；拆 `Sense`/`Example` 会牵动渲染，留到第 4 步。
- **D5 旧函数保留**：`translate_en_to_zh` 仍返回字符串；`lookup_word` 改为返回 `Definition`（仓库内只有 `app.py` 调用，已同步）。
- **D6 线程模型**：第 1 步不动；第 2 步改为“请求号 + 取消事件”，新的顶掉旧的。仍是一次请求一个线程，单队列未做（见 D8）。
- **D7 不加依赖**：测试用标准库 `unittest`；HTTP 仍用已有 `requests`。
- **D8 用请求号代替单队列**：行为等价（只有最后一次可见），实现更小；不做线程池/队列。
- **D9 配置放用户目录**：`%LOCALAPPDATA%\翻译小助手\config.json`，不再跟 exe/脚本走；解决打包后临时目录丢配置。
- **D10 用 DPAPI 而不是凭据管理器**：不加新依赖、天然支持多方案；代价是换机器/换用户解不开，需要重填钥匙。
- **D11 不抢前台焦点**：后台显示用 `SW_SHOWNOACTIVATE`；只有已在前台才 `focus_force`；点外面用鼠标轮询兜底，避免任务栏/关闭按钮闪烁。

## 9. 术语

- **Intent（意图）**：用户这次到底要什么，只有“查词”和“翻译”两种。
- **Result（结果）**：做出来是什么，只有“译文”“词典”“失败”三种。
- **适配器**：把一种输入翻译成另一种输入的外壳，本身不含业务判断。
- **原子写**：先写临时文件再整体替换，写一半断电不会留下半个坏文件。
- **流式**：模型边生成边往回吐字，不用等整段完成。

### 验证

- 45 条单测全绿；`py_compile` 9 个文件通过。

## 14. 验收反馈：任务栏/关闭按钮闪烁（2026-10-24）

### 原因

- 每次弹窗调用 `focus_force`；Windows 前台锁允许时正常，拒绝时闪任务栏按钮。
- 第一版把主窗口设成工具窗口，任务栏按钮没了，但闪烁转移到标题栏关闭按钮（用户反馈灰方块会闪）。

### 修法

- 恢复普通窗口：正常标题栏、标准关闭按钮、任务栏按钮。
- 后台显示用 `SW_SHOWNOACTIVATE`，不抢焦点；只有已在前台才 `focus_force`。
- 点窗口外面藏起改为鼠标轮询兜底：按下在窗外，松开时仍不在前台且不在窗内才藏。
- 关闭按钮只隐藏窗口，退出仍走托盘。

### 验证

- `SW_SHOWNOACTIVATE` 实测：窗口可见，但没有抢到前台。
- 48 条单测全过；exe 重打。
- 实际不闪需用户重启后看。

## 15. 布局改为译文优先（2026-10-24）

### 原因

- 用户复制英文后，原文是已知信息，译文才是答案；长原文占上半屏，把译文推到下方。
- 弹窗第一眼应该落在“译文”标题和第一行中文。

### 做法

- 上下顺序反过来：译文在上，原文在下。
- 原文默认 3 行 + 滚动条，可点“展开”；展开最多占 70%，译文仍在顶部。
- “复制”移到译文标题旁；底部只留“翻译剪贴板”“翻译输入”。
- 窗口高度由译文和紧凑原文决定，不再由原文长度决定。
- 结果出来时 `see("1.0")`，保证译文从第一行开始显示。
- 查单词时原文收成 1 行（词头已在词典里）。

### 验证

- 真实 Tk 窗口 + App 方法实测：长原文短译文，译文 312px、原文 93px；原文框可滚动；展开后译文 196px、原文 226px；词典原文 55px。
- 48 条单测全过；`py_compile` 通过。
- 实际观感需用户按第 8 节第 18–20 条看。
