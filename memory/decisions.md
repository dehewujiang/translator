# 决策记录

1. 拆分选 A 保守拆不选 B 彻底拆：翻译流程和渲染易碎，动它们收益小风险大；用户拍板 A。
2. 风格选 Win11 原生风：跟系统自带一致最耐看，Tk 也能实现；用户三选一拍板。
3. 提示词定稿用"顺但不改术语"版：用户看英文文档，直译太硬，全意译又怕走样；词典通道走程序写死指令用户提示词只管句子。
4. 界面重做先出效果图再动代码，不靠形容词来回猜：用户说"丑但不知道要求什么"，给两张只差一处的图（有无标题栏）让他按图拍板；选了无边框。
5. 无边框用 `overrideredirect` + `-transparentcolor` 抠角，不用换框架：收益是无边框+圆角，代价是丢掉系统阴影、任务栏与 Alt-Tab 条目；换 Qt 能做阴影动效但要重写全部界面、体积翻 4 倍，不值。
6. 配置窗换 tk 不换 ttk：ttk 控件不吃 `option_add("*Font")`，以前怎么设都是宋体；tk 控件才能显式控字体与配色。
7. 状态提示改挂顶栏左侧，不让窗口长高：长高会让窗口在复制时抖动；顶栏左侧本来就是空的。
8. 拖矮时收文本框行数，不抬高拖拽下限：下限抬到内容高度会让"拖矮"在长译文上完全失效；收行能让窗口缩到 360，译文靠滚轮看全文，按钮永远在。代价是拖矮后译文区显示行数变少（可接受）。
9. DPI 适配选"声明感知 + 全量 px() 换算"，不换框架：真机 125% 下原来整窗被系统拉伸发虚；换 Qt 要重写全部界面且体积翻倍，不值。代价是每个像素常量都要过 px()，新代码必须守规矩。
10. 确认框异常一律 fail-closed：删除/关窗这类不可逆或丢数据的操作，对话框坏了宁可不动，也不赌用户点的是确定。
11. 列表"正在用"用 selectforeground 动态设置，不逐项设字体：Tk Listbox 不支持 `-font`，异常被吞后既不生效也不报错；选中态本来就会用 selectforeground 覆盖文字色，按选中项动态设它最省事。
12. 译文区只读 + 临时解锁写入：避免用户误改结果，同时保留选中复制；所有写入走 `_dst_edit`，异常也能锁回去。
13. 深色模式跟随系统、启动时读取，不做运行中热切换：热切换要重建全部控件，收益低风险高；启动读注册表够用，另有 TRANSLATOR_THEME 供测试。
14. 深色标题栏用"ForceDark + 建窗时短暂摘色键 + DWM"组合：单独任一都不生效；代价是开窗一帧内主窗透明边可能露色，属可接受瞬态。
15. 滚动条自绘，不用系统滚动条：系统滚动条在深色下是白底带箭头，和整体不搭，且无法只显示滑块。
16. 宽度拖拽只记本次运行、不落配置：避免改动配置 schema；需要记住宽度再另议。
17. 测试连接直接复用 provider.chat 发一条最小请求，不做 /models 探测：各家兼容层对 /models 支持不一，最小对话请求最接近真实使用。
18. app.py 暂不拆：1820 行、97 个函数，大头是建窗/布局（约 606 行）和拖拽/尺寸（443 行），都是共享 self 状态的展示层代码，拆成 mixin 只是搬行数、不降耦合，L3 回归风险高、用户收益为零。触发再拆的条件：文件超过约 2000 行且还在涨 / 需要单独测试交互逻辑 / 有第二个人同时改它。真要做时，优先把"拖拽/尺寸"整块抽成 translator_interaction.py（已有 drag/resize 测试兜底）。
