# 踩过的坑

1. 分身间不拆：合入文件后忘了 `git worktree remove`＋删分支还拿 gitignore 掩盖。以后施工图并行组后默认加"拆房"节点（harness gateflow 关 6 已补一句）。
2. 全角逗号目测漏掉：CJK 转录别信眼睛，搬家后一律程序化逐字节比对。
3. 状态栏单引号：Windows 命令行不认单引号，跨平台命令写独立脚本文件别拼 `python -c`。
4. 截图看不出布局 bug：状态条把底栏压成 2px 这种问题，截图时恰好没状态字就发现不了；只能靠运行时探针量 `winfo_height()`。以后改 pack 布局一律补一条"改动前后各量一次"的脚本检查。
5. 自己写的测试桩会骗自己：`create_empty_profile` 本来就负责落盘，我把它换成空操作后误判"新增没生效"。桩要按真实职责写，判 bug 之前先确认是产品的问题还是桩的问题。
6. 效果图能省掉一轮返工：用户说不清要什么时，先出图（两张只差一个决策点）比问十个问题快；但效果图里的"死白"要按真实内容高度给，给成固定大画布会显得像坏了。
7. 验收单不能写文件名/函数名：收工门会判不合格，验收单只写"你在哪儿→做什么→该看到什么"，机器证据放"验了什么"和"证据在哪"。
